## 重启前检查单（编排者逐项签署）

- [ ] 暂停派新单，通知两个团队窗口起止时间与负责人；所有活动回合完成交接，不在流式回答/工具执行中退出。
- [ ] r2 负责方确认进程自然完成、退出码已收取；进度达到完整终值，事件尾部有完成记录；全量三件套、分区/检查点及输入身份已冻结，附 SHA256 清单和独立持久副本。心跳停止或 CPU 下降不算完成，checkpoint 预演不算全量终算。
- [ ] 所有 Bot 收取仍相关的后台 job 结果；没有 running/provisioning 回合、测试、扫描、git 操作、备份或迁移。除 job 工具外，任务启动者还要确认独立终端/WSL/其他宿主的进程已结束；不以杀进程收尾。
- [ ] 无在途下载、自动更新或安装。菜单 B 的更新包应在此之前从官方渠道准备并核验发布者/签名及官方摘要（若提供），验证完成后才进入窗口。
- [ ] 逐会话查询完整触点列表（含所有页）：没有 active 项；历史项均已 ended，或已有明确暂停/删除记录。暂停不冒充 ended；如未来提醒需保留，先登记并由编排者安排窗口后恢复，不擅自删任务。不得依赖“重启会清掉触点”。
- [ ] 每位成员核自己的分支、HEAD、工作树与索引；本人修改本人提交，推送前 secret_scan/gitleaks 双扫全0，再由获授权者推任务分支。逐项核本地 HEAD 与远端 SHA。保留未合 PR，不把已提交当成已推送。
- [ ] 未提交 WIP 由本人保存并做仓库外受控副本，记录恢复路径与校验值；不替他人 stash/reset/提交，不清理工作树。只在本机安全存储原始 WIP，不把私密材料为方便备份而入库。
- [ ] 仓库外结果、忽略文件、原始日志和证据独立备份并核 SHA256；例如团队持久证据目录 `F:\workspace\team\probes\` 及 r2 负责人指定的冻结目录。不得只留在待清理 worktree 或临时目录。
- [ ] 待办池、报告、窗口签署单与未完成项已写盘；应用内已保存长期记忆。记忆只是摘要，任务恢复必须能找到原始文件、提交和证据路径。
- [ ] 两款应用的会话/配置数据通过其实际支持的导出或备份途径保存并验证；如无可靠导出，先正常退出、确认写盘，再对实际数据目录做受控离线副本。路径以当前配置/官方说明为准，禁止猜目录、删除缓存或边运行边拷贝状态库。离线备份未完成前不更新软件。
- [ ] 用户/编排者签署具体菜单和时间；记录执行人、旧版本、官方安装包来源、应用状态备份位置与回退入口。私密路径和原始内容仅留本机受控记录，仓库报告只记完成状态。

“无损”的依据是逐层可验证的持久化：代码/文档依赖本地提交和远端副本，未提交文件依赖受控副本，实验产物依赖冻结文件和校验清单，会话/记忆依赖应用状态备份。**Git 不保存忽略文件，GitHub 不保存未推提交，记忆不保存运行中的计算。** 因此不承诺未满足上述条件的运行任务可以靠重启恢复，也不自动恢复或重跑 r2。

## Grok Bot 更新步骤（菜单 B）

1. 先在 Grok Bot 界面确认无活动任务，完成保存/导出；关闭窗口后继续从 Windows 托盘右键选择应用“退出”。仅关窗口可能只是最小化到托盘。
2. 从独立 Windows PowerShell 或任务管理器检查残留。先比对进程完整可执行文件路径、PID、父 PID 与启动时间；同名多个进程可能是正常渲染/辅助进程，不代表可以直接全杀。
3. 托盘退出后仍有残留，先等待应用正常写盘/退出；只有确认是该已退出 Grok 实例的残留、无下载/更新/任务并且状态副本已保存后，才对**逐个确认的 PID**结束进程树。访问被拒绝即停报编排者；不扩权，不按 `node`、`python`、`electron`、`pwsh` 或通配名批量杀进程。不要停止 DSH、Docker、WSL 或 A 股服务。
4. 确认 Grok 实例全部退出，完成离线状态副本后，按官方安装器/更新器执行 0.79.4 更新。若官方流程要求应用内下载，先在窗口前下载完，再进入其正式退出安装步骤；不要把等待下载算作已静默。
5. 启动 Grok，核“关于”页显示 0.79.4，旧会话、团队、设置、记忆与交接入口可读；用一条本地只读动作确认可工作。保留麦蕊停用状态和既有授权边界，禁止为验收触发真实调用。
6. Grok 验收失败，停止菜单 B 后续步骤，保留错误与安装日志，按下节恢复；未验收前不继续重启 DSH。

下面仅是执行窗口内供操作者运行的**只读识别命令**，本单未执行任何退出/结束进程操作。安装位置如变化，先核实际路径再比较，不打印命令行参数或环境变量。

```powershell
$grokExe = 'D:\Grokbot\Grok Bot\Grok Bot.exe'
Get-CimInstance Win32_Process -Filter "Name='Grok Bot.exe'" |
    Where-Object { $_.ExecutablePath -eq $grokExe } |
    Select-Object ProcessId, ParentProcessId, ExecutablePath, CreationDate
(Get-Item -LiteralPath $grokExe).VersionInfo.ProductVersion
```

结束残留通过任务管理器“详细信息→核完整路径/PID→结束进程树”逐个操作；本文不提供未经现场身份核验的一键终止命令。若路径不可读取则该进程身份未确认，不能据名称强制终止。

## DSH 正常重启（菜单 A，或 B 的 Grok 验收之后）

1. 编排者再次确认所有会话静默、结果已收取；保存当前 GUI 地址、待恢复会话和窗口签署单。当前会话地址为 `http://127.0.0.1:60008`，恢复时以实际应用显示为准，不另启服务来模拟旧 GUI。
2. 由应用正常退出入口/托盘退出 DSH；操作人须使用独立终端或系统界面。不要让 DSH 内部工具调用强杀自己的宿主，避免未返回的工具结果和未写盘会话。
3. 确认 DSH 退出后完成其状态目录离线备份（如采用该方式）。不要删除 profile、数据库、记忆、缓存或凭据；不顺手升级 DSH，本菜单只重开现有版本。
4. 用原快捷方式/安装入口启动相同 profile；打开原 GUI 或应用给出的地址，检查旧聊天、团队成员、记忆、工作目录与待办池。查看遗留任务状态，不自动重新提交未明状态的任务。
5. 执行一次只读核验：项目目录可读、任务分支 HEAD 与签署记录一致、冻结产物 SHA256 不变；查看触点与 job 是否出现重复/意外恢复。不得自动重建已停麦蕊触点。
6. 确认原有本地 A 股服务状态与窗口前一致后，编排者恢复派单。应用能打开不等于 r2 已通过；独立终算/评审仍按原门禁继续。

## 失败处置与恢复顺序

- 更新失败或版本不符：保持另一应用不动，收取脱敏错误摘要并交编排者。先按官方修复途径恢复；只有官方支持旧版本和状态格式兼容时，才使用已验证的旧安装包及对应离线状态副本回退。不能把旧二进制直接套在已升级状态库上。
- 会话/记忆缺失：先核启动 profile 是否一致，停止新写入；保留故障状态副本，经编排者确认后按应用支持方式恢复备份。不可删除 profile“重装试试”。
- 发现 WIP/证据未落盘、仍有活动任务或在途下载：选 C，取消本次窗口；不通过杀任务或删锁制造前置通过。
- 任何数据/权限异常：停在当前步骤，报告受影响对象及已验证副本；不改 ACL、不切属主、不停止数据库、不执行 `down -v`。无可验证回退时保持停机并升级给编排者。
