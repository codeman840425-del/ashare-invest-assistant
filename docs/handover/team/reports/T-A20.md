# T-A20 可信交互会话与历史审核（架构师 2026-11-07）提交 1f8e455（契约 §7.4，本地未推送，扫描 0/0）
- ① 可信交互会话 = 服务端会话带 origin:"password_login"（只在 /auth/login、/auth/password 写入；令牌或其他途径建立的会话没有）+ cookie + CSRF + 本次请求重新输入本人密码。
- 密码错误 → 401 REAUTH_FAILED，计入登录失败锁定。密码只核对，不落库、不进日志或审计。不设最近登录时间窗口。
- 适用：POST /admin/promotions/{id}/decision（body 加 password）和 lifecycle draft→simulating（body 加 password）。
- ② 无绑定的历史审核：一律 stale，stale_reason=legacy_unbound，version_id/content_sha256 为 null，不补算哈希，详情和列表返回 200（去掉 503）。只读，要晋级须重新申请。
- 后端 T-B83：SessionStore 加 origin，登录和改密时写入；两条写入口校验 origin 与 password（复用密码哈希核对和锁定计数）；接通决定持久化、合规文案校验、成功审计（不含密码）、生命周期变更；加 stale_reason；做正链验收。
- 前端：决定和晋级弹窗加密码框（autocomplete=off，不预填）；处理 401 REAUTH_FAILED 和 stale_reason。
- 团队规则：代理和脚本不得代填该密码框；G7 只能由用户本人点。
