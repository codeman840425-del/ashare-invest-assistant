# T-A40 裁定：T-B91 B1 买入/加仓草案的两个口径（最小可行，2026-11-08）
依据：plan §2.5.8 数量取最小值的五项、§2.5.9 STRATEGY_BUDGET_EXHAUSTED；reports/T-B91.md（f28727d）
## 1. 本笔最大亏损的来源
- Phase 2 不新增配置键。契约 §7.11.2 和 RC1–RC6 都没有用户可设的“单笔最大亏损上限”，模板 risk_suggestions 只是展示文案，不作为约束。
- 所以“单笔最大亏损 / (参考价 − 止损价)”这一项在 Phase 2 视为未配置：跳过这一项，不报 gap、不拒绝；数量由其余四项取最小值。不凭现金或资产比例自造上限。
- 草案仍要输出结果值：max_loss_amount = qty_range.max × (参考价上限 − stop_loss) + 买卖费用估算，max_loss_pct = max_loss_amount / 总资产。总资产未知时 pct 为 null 加 gap；没有 stop_loss（RC1 关闭）时两者都为 null，并带 RC1 关闭警示。
- 以后若加上限配置，单独走契约变更，不在 T-B91 范围内。
## 2. 实例预算已用额度的归属
- budget_amount 为 null：预算项不约束、不报 gap，STRATEGY_BUDGET_EXHAUSTED 不触发。
- budget_amount 非空时，已用额度 = 该用户名下状态为 active/triggered、action 为 buy/add 的计划之和。每个计划取最新版本的金额：qty×price；缺其一则用 size_amount；三者都没有就是 unknown。
- 计划归属：按 plan_versions v1 的 candidate_signal_ids → 候选信号的 instance_id 找实例；多实例来源的计划按全额计入每一个来源实例（保守，宁可多算）。
- 不按导入持仓或成交反推；该值标为 estimate，用户上下文快照记 budget_used、budget_amount 和参与计算的 plan_ids。
- 任一参与计算的计划金额为 unknown：预算项 unknown，buy/add 草案按现有逻辑拒绝并给出 gap；sell/reduce 不受影响。
- 本草案是多实例来源（instance_id 为 null）时，预算剩余取各来源实例剩余额度的最小值；任一实例为 unknown 就按上一条处理。
- 剩余额度 ≤ 0 时触发 STRATEGY_BUDGET_EXHAUSTED，不生成买入草案。
## 归属
- 后端在 T-B91 B1 内按上述实现，并补测：两项都为 null 时正常出草案；预算耗尽；多实例按全额计入；金额 unknown 时拒绝。
- 架构师在收尾时把本裁定并入契约 §7.11.4，本次不改 docs。
