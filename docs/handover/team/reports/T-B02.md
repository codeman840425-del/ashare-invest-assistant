### 8.2 启动命令（同一个后端镜像，WORKDIR=/app/src/backend，PATH 里有 /opt/venv/bin）

| 服务 | command | healthcheck |
|---|---|---|
| api | 不变：`uvicorn app.main:app --host <host> --port 8000 --proxy-headers --forwarded-allow-ips *` | `/api/v1/health/live` |
| worker | `python -m app.workers.worker` | `python -m app.workers.healthcheck worker` |
| beat | `python -m app.workers.beat` | `python -m app.workers.healthcheck beat` |
| ingest | `python -m app.workers.ingest` | `python -m app.workers.healthcheck ingest` |
| signal-rt | `python -m app.workers.signal_rt` | `python -m app.workers.healthcheck signal-rt` |

**行为**
- 启动时和 api 一样严格校验 config。遇到未知键会以退出码 1 退出，实测输出 `bogus_key: Extra inputs are not permitted`。
- 进程常驻，每 15 秒打一条日志，并写一次存活文件 `$AIA_ALIVE_DIR/aia-<名字>.alive`（默认放在 /tmp）。
- 收到 SIGTERM 或 SIGINT 后，在 1 秒内以退出码 0 退出，并删除存活文件。
- healthcheck 规则：存活文件 45 秒内更新过，退出码为 0；否则为 1；参数非法时为 2。
- 需要的环境变量：`CONFIG_DIR`、`LOG_LEVEL`；ingest 还需要 `REDIS_URL`。worker、beat、signal-rt 目前不连接任何依赖。

**ingest 心跳**
- 按 `ingest.yaml heartbeat.interval_s` 的间隔（15 秒）执行 `SET ingest:heartbeat <json> EX 600`。
- 实测 JSON：`{"ts":…,"instance_id":"<host>:<pid>","leader":true,"version":"0.1.0","budget_used_last_minute":0,"queue_depth":{"p0":0,"p1":0,"p2":0}}`，TTL 为 596，相邻两次 ts 相差 15 秒，/health/ready 判为 ok。
- 键名和 /health/ready 读取的是同一个设置（`INGEST_HEARTBEAT_KEY` 可以覆盖）。
- 占位进程**不发任何外部请求，也不读取 licence**。

### 8.3 migrate 命令（一次性服务，在 api 启动前执行）
- **前提，需要运维处理：** 现在的 dockerignore 白名单和 COPY 只包含 `pyproject.toml`、`uv.lock` 和 `app/`。需要再加上 **`alembic.ini` 和 `migrations/`**，否则镜像里跑不了 alembic。
- 迁移本身（容器内执行，DATABASE_URL 用 compose 已经拼好的值）：
  ```
  alembic upgrade head
  ```
- 完整的一次性流程（在宿主机执行。脚本通过 docker exec 进入 postgres 容器，所以 apply 这一步必须在宿主机上跑）：
  ```
  docker compose … run --rm --no-deps api alembic upgrade head && deploy/scripts/db-apply-timescale.sh
  ```
