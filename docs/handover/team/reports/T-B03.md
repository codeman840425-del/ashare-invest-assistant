## 实现
| 端点 | 行为 |
|---|---|
| GET `/meta/registration` | `{mode}`，来自环境变量 `REGISTRATION_MODE`，默认 `closed` |
| POST `/auth/register` | `closed`/`invite` → 503 REGISTRATION_CLOSED；`open` → 201 `{id, username, status:"pending"}`，并写三条同意记录；重名 → 409 CONFLICT |
| POST `/auth/login` | 200 `{user: Me, csrf_token}` + Set-Cookie。用户不存在或密码错 → 401 INVALID_CREDENTIALS（不存在时也跑一次哈希，耗时接近）。`locked_until` 未到 → 403 ACCOUNT_LOCKED{retry_after_s}。密码正确但未批准 → 403 ACCOUNT_NOT_APPROVED{status, reason?}（reason 取最近一次驳回原因），**不建会话** |
| POST `/auth/logout` 🔒 | 删除会话、清 Cookie → 204 |
| POST `/auth/password` 🔒 | 旧密码错 → 400 VALIDATION_ERROR(old_password)；新密码按策略校验且须与旧密码不同；成功后写 `password_changed_at`、吊销其他会话、保留当前会话 → 204 |
| GET `/me` 🔒 | Me：`entitlements={}`（归 T-B28），`consents` 取每种最新且 granted 的记录（`privacy_policy` 显示为 `privacy`），`risk_assessment` 取最新画像的 risk_tolerance + confirmed_at |
| GET/PUT `/me/profile` 🔒 | 只追加新版本（`version_no` = max+1，唯一约束冲突 → 409 VERSION_CONFLICT）。无画像 → 404。pct 只收十进制字符串，范围 5–50、最多 2 位小数（同 Rc2PositionCap）；horizon 非空、不能重复 |
| POST `/me/consents` 🔒 | key ∈ {signal_risk_disclosure, privacy, terms} → 201 `{key, version, accepted_at}` |
<redacted:sensitive-value-or-command>

- **密码**：argon2id（64 MiB / t=3 / p=1）；登录时检测到旧参数会自动重新哈希。策略：10–128 位，须同时含字母和数字，不在常见弱口令表中，不等于用户名（忽略大小写）。
- **会话**：存 Redis `auth:session:{sha256(sid)}`，明文 sid 只在 Cookie 里，7 天滑动 TTL；按用户建索引，用于吊销。登录时作废旧会话（防会话固定）。
- **CSRF**：双提交。Cookie `csrf_token`（非 HttpOnly）+ 请求头 `X-CSRF-Token`，与会话内令牌做常数时间比较；POST/PUT/PATCH/DELETE 都要求。
- **Cookie**：`sid` 带 HttpOnly; SameSite=Lax; Path=/; Max-Age=7d；Secure 由 `SESSION_COOKIE_SECURE` 控制（默认 true）。
- 已登录用户状态变为非 approved 时，下一次请求返回 403，并吊销该用户全部会话（兜底；正式的禁用即吊销归 T-B03b）。
- **审计**：audit_logs 记录 register / login / login_failed / logout / password_changed / profile.updated / consent.granted / risk_assessment.submitted。`ip_hash` = HMAC-SHA256(APP_MASTER_KEY, ip)，不记明文 IP，也不记密码。
- 密钥（DATABASE_URL、REDIS_URL、APP_MASTER_KEY）只从环境变量读取；代码和自检里没有真实密钥，自检的口令与主密钥都在运行时随机生成。
- **迁移 0004**：`ck_consents_kind` 增加 `terms`；给 `max_single_position_pct` 加列注释。upgrade/downgrade 往返（base↔head、0003↔head）通过，`alembic check` 无差异。
- **依赖**：新增 argon2-cffi 25.1.0（pyproject + uv.lock）。

## 保守决定（需架构师确认）
1. 用户名采用 plan/DB 的 4–32 位 `[a-z0-9_]`，统一转小写；契约写的是 3–32，取更严的一边。另保留 admin/root/system 不可注册。
2. `invite` 模式下没有邀请码表和发放、核验接口，无法核验，所以同 closed 返回 503。
3. 注册 `agreements` 必须恰好是 {terms, privacy, risk_disclosure}（契约未列取值，按 plan §3.6 命名）。注册时的 `doc_version` 先填 `"unversioned"`，等文案版本来源（T-B15）。
4. plan §3.3 的 consents.kind 没有 `terms`，由迁移 0004 补入。
5. 风险测评的题目和计分规则在 plan、契约、研究文档里都没有，所以**没有自拟**。只提供问卷结构和计分框架（`app/auth/risk_assessment.py`）；问卷未配置时返回 400 `questionnaire not configured`。自检注入的是测试问卷。
6. PUT 画像时若改了 risk_tolerance，就清空 confirmed_at，`/me.risk_assessment` 变为 null（需重新测评）；未改则保留。
7. 改密旧密码错返回 400 VALIDATION_ERROR，而不是 401，以免前端误判为会话失效。
8. 会话 TTL（7 天）和 argon2 参数先写成常量，plan §6.1 没有对应配置键。
9. 失败计数、渐进锁定、login_attempts、限速（429）、pending 上限、蜜罐归 T-B03a；管理员审核、禁用即吊销归 T-B03b。本单只读取 `locked_until`。
