| 模块 | 内容 |
|---|---|
| `upstream.py` | 把麦蕊响应归成调度信号。先看响应体里的 `error`，再看 HTTP 状态码。<br>· 101 → 额度用完<br>· 102 → 证书无效<br>· 103 / 429 → IP 超限<br>· 503 默认当作频率类；调用方标了 `data_missing_503` 时当作数据缺失<br>· 403 → 接口未开通<br>· 5xx 和网络错误单独归类 |
| `bucket.py` | 每张证书一个令牌桶，突发上限为 10 秒的量，支持热调。另有按北京时间自然日的计数器，用于钻石版过期后的每日 20000 次。 |
| `state.py` | 每张证书的状态机，规则见下表 |
| `scheduler.py` | 每张证书有 P0/P1/P2 三级队列。<br>· 先比优先级，同一级内按 DRR 轮转（quantum 1，可配）<br>· 全局并发 2，每张证书并发 1<br>· 删除证书时直接丢掉它排队的请求，不转给别的证书 |
| `core.py` | 把状态机、令牌桶、调度器组合起来，提供 `next_call` 和 `complete`。`verify_licence` 意图在 pending 状态下也放行。 |
| `vault.py` | HPKE 解封：按行的 `seal_key_version` 选私钥，AAD 绑定用户和行。私钥用 `load_private_keys()` 从 `/run/secrets` 读。<br>对所有已加载的证书明文做 `***` 替换（文本和字节都处理）；`repr` 里不含明文。 |
| `intents.py` | 解析 `verify_licence` 意图。记录里如果带 `licence` 字段就拒绝，因为明文不能经过 Redis。<br>`per_licence` 模式下：`source_licence_for` 只返回用户自己的证书，证书不可用时返回 None（对应 `gaps[].reason=data_licence_unavailable`），不会改用别人的证书；`readable_by` 判断用户能读哪些行。 |
| `expiry.py` | 到期前 30、7、1 天各提醒一次。漏掉的提醒只补最近的一档；幂等键里带上到期日。 |

状态机规则：

| 上游信号 | 处理 |
|---|---|
| 102 | 进入 `invalid`，不自动重试；用户重新 PUT 或点测试后转为 pending |
| 101 | 进入 `quota_exceeded`，暂停到北京时间次日 00:01 |
| 103 / 429 | 暂停 120 秒；1 小时内第 3 次改为暂停 1 小时，并通知用户和管理员 |
| 频率 503 / 5xx / 网络错误 | 依次退避 1、2、4、8、16、32、60 秒；连续 5 次熔断 300 秒，并通知管理员 |
| 数据缺失 503 | 不改变状态 |
| 超过到期日 | 进入 `expired`。钻石版只保留 P0，并受每日上限约束；其他档位停止 |
| 管理员暂停 | 进入 `paused_by_admin`，用户操作和成功响应都解除不了；管理员恢复后转为 pending |
