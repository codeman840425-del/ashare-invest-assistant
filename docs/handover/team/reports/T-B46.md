## 1. 实现范围
| 端点 | 说明 |
|---|---|
| `GET/POST /accounts` | 列表分页；创建限速 20 次/小时/用户；`owned_account()` 供其他路由校验归属 |
| `POST /imports` | multipart，**单文件**。只收 .txt/.csv，拒 NUL，单文件 5 MiB（`max_file_bytes`），整个请求 26 MiB（超过 → 413 PAYLOAD_TOO_LARGE）。上传后用 BackgroundTasks 解析，返回 `{batch_id, status:"uploaded", file_findings}`。限速：上传 30 次/小时，写操作 120 次/小时 |
| `GET /imports`、`/imports/{id}`（弱 ETag/304）、`/imports/{id}/rows` | 预览、明细、提示（findings） |
| `PUT /imports/{id}/options`、`POST …/findings/{fid}/resolve` | 复用 `importing/resolutions.py`；resolve 后**同步重新解析** |
| `POST …/confirm`、`…/discard`、`…/revert`、`GET …/errors.csv` | revert 只作废成交（触发器禁止删除），状态不对 → 409；errors.csv 带 BOM、CRLF、`charset=utf-8`，**包含 warning**，不含明文 |
| `GET/POST /trades`、`GET /trades/{id}`、`POST /trades/{id}/void` | 手工录入用 Idempotency-Key；更正（`corrects_trade_id`，必须同一账户）；作废；`include_voided`；`from`/`to` 只收 `YYYY-MM-DD`；复用 `domain/trades.py` |
| `GET /portfolio?account_id=` | account_id 可选，缺省合并全部账户。弱 ETag，If-None-Match → 304 无 body，`Cache-Control: private, no-cache`。ETF 进持仓，但不跑策略 |

- 解析器：通达信成交明细 `tdx_trades_v1` 和资金持仓 `tdx_positions_v1`，按定宽切分（plan §3.5A 的策略 a+b）。编码判定支持 gb18030/utf-8。
- 隐私：
  - <account-field>只存 HMAC + 掩码；席位代码、<account-field>直接丢弃。
  - 原始文件放在仓库外的 `IMPORT_STORAGE_PATH`，AES-256-GCM 加密，每个文件一个 DEK，主密钥取 `APP_MASTER_KEY`。
  - raw_line 先掩码再加密。响应、errors.csv、日志里都没有明文（自检逐项核对过）。
  - 删除用户数据时一并删除原始文件（`cli/delete_user_data.py`）。

## 2. 问题 63：可转债展示
- 按 `import_as_is` 导入时**保留原代码**（例如 113050.SH），不写进证券主数据。
- 持仓里给出 `instrument_kind:"convertible_bond"`。现价、市值、盈亏是 `null`（前端显示“—”）。总仓位、集中度按成本估算，并标 `estimated:true`；顶层也有 `estimated`。portfolio 的 `gaps` 里会说明原因。
- 不跑策略、不出信号、不进风控止损计算：统一走 `strategy.eligibility`，ETF、可转债、未知类型都是否。
- **新增字段（附加、最少，请架构师确认）**：`Holding.instrument_kind`（stock/cdr/etf/convertible_bond/unknown）、`Holding.estimated`、`Portfolio.estimated`。
