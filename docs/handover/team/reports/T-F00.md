## 4. 设计取舍
1. **表格用 AntD Table，不用 AG Grid**；**布局固定三栏，不用 react-resizable-panels**。plan §2.10 写的是 AG Grid 和可拖拽面板，本任务明确要求 AntD，原型只为确认风格和信息密度，后续正式骨架再按 §2.10 评估。
2. **自写约 15 行的 hash 路由**，没引 react-router，原因是要保证 fil<path> 能用、依赖最少。
3. **fil<path> 兼容**：输出格式设为 IIFE、单包、CSS 内联进 JS，并用一个小插件把 `type="module" crossorigin` 改成 `defer`。代价是没有代码分割（gzip 后约 410 KB），原型可以接受。
4. **红涨绿跌**（A 股习惯）；分歧徽标用醒目的黄底；被阻断的原因用橙色块。
5. **措辞**：动作统一写成“规则信号：××条件满足（候选）”，卡片名叫“候选信号卡”，草案里用“计划条件”。全程不出现“推荐”或“立即买卖”。分歧只报计数并列展示，**不合成单一结论**。
6. 分时时间轴按“北京时间当作 UTC”喂给 lightweight-charts，午休不留空。lightweight-charts 的署名 logo 保留（Apache-2.0 许可要求），页脚也注明了。
7. TS 类型集中在 `src/types/contract.ts`，字段名照契约用 snake_case，金额和价格保持十进制字符串；契约没写、原型自己假设的字段用 `// [原型假设]` 注释标出。

## 6. 不一致与遗留问题（未改契约，请契约负责人确认）
1. **§2.5.5 `dimension_views[].rules[]` 用 `pass` / `evidence_id`（单数），契约 RuleRef 用 `passed` / `evidence_ids`（数组）。** 原型两种都按原文实现（`DimensionRuleResult` 和 `RuleRef` 分开），需要统一。
2. **§2.5.5 `invalidation` 示例是 `{expr, evidence_id}`，契约 P1 是 `TextWithEvidence{text, expr, evidence_ids}`。** 原型按契约实现。
3. **plan §0A.2 用 `evidence_id`，而 Evidence 对象主键叫 `id`**，引用字段命名需统一。
4. **维度分的口径**：§2.5.5 示例 `score: 0.83`（0–1），契约 §1 写“0–100 整数分数”。原型用 0–100。
5. **止损止盈结构不一致**：CandidateSignal 是嵌套 `stops{stop_loss,take_profit,time_stop_days}`，Suggestion.strategies 是平铺的 `stop_loss`/`take_profit`，而且没有 `time_stop_days`。
6. Suggestion.strategies **缺少策略显示名**（只有 `strategy_key`）以及**和 candidate_signal 的关联字段**。原型自加了 `candidate_signal_id`，`t_leg` 也是自加的（§2.5.5 未列）。
7. Suggestion 头表的 `status`（active/superseded…）在 §2.5.5 正文里没有；`executability.status` 的取值集合没有定义，原型假设为 executable/blocked/not_applicable。
8. **`dimension_matrix.cells` 只有 `view`**，矩阵单元格要显示的维度分和关键证据需要另从 `strategies[].dimension_views` 拼。原型加了 `score`/`key_evidence`（假设），建议契约明确。
9. **契约没有给出结构的对象**：`/securities/{code}/bars` 的元素（OHLCV 字段名、分时均价）、盘后日报 `/reports/daily/{date}` 的结构、自选列表元素、**证券简称 `name`**（quotes/portfolio/suggestion 都没有，终端表格离不开）、通知列表的 `created_at`/`read`/跳转目标、SSE `signal.kind` 的取值集合。
10. **终端聚合接口没有定义**：终端一屏要用到自选、行情、持仓、各证券最新 Suggestion 摘要（动作徽标和分歧），`/today` 的返回结构也没有定义，现在需要前端发 N+1 个请求或由后端新增聚合接口。
11. 盘后日报里的账户 `market_regime` 及其建议仓位区间、对账状态（matched/diff/not_imported），契约没有字段。
12. 设计偏差（plan §2.10）：AG Grid 和可拖拽面板没有采用（见第 4 节），正式骨架需要决定是否沿用。
