# T-F21 性能与窗口加载（契约 v0.2.7）

- 提交：`717bce0`（只含 src/frontend/，19 个文件，+760/−67；本地提交，未 push）
- 依据：契约 v0.2.7 §1.2 游标分页（`limit` 默认 50、上限 200，`next_cursor`）；§7.3 `GET /securities/{code}/bars` 的 `before`+`limit`（默认 500、上限 2000）→ `next_before`，以及“`adjust_as_of` 变化时客户端须丢弃已缓存 K 线并重载”；plan T-F21“K 线窗口加载、表格虚拟化、批量更新”。

## 改动

| 项 | 实现 |
|---|---|
| K 线窗口加载 | 新增 `useBarsWindow(code, freq, pageSize)`：`useInfiniteQuery` 以 `before` 为页参数、`next_before` 取下一页。合并用 `mergeBarPages`（升序、按 `t` 去重）。个股日 K 首屏 250 根，周 K 120 根，终端日 K 120 根 |
| 拖到左边缘 | `KlineChart` 订阅可视逻辑区间：左端距首根少于 10 根（`REACH_START_BARS`）时调用 `onReachStart` 取更早一页；数据前插后按新增根数平移视图（`shiftView`），视图不跳动 |
| 窗口信息 | `KlineWindowInfo`：“已载入 N 根日/周 K”，加载中 / 加载失败 / 已到最早三种后缀，按钮“‹ 更早”（失败后为“重试”） |
| 失败处理 | 更早一页失败时已载入的 K 线保留，只在窗口信息里提示；失败后拖动不再自动重试，避免请求风暴，点按钮才重试。只有首页失败才显示错误框 |
| `adjust_as_of` | 首页的 `adjust_as_of` 与同证券其他缓存不一致时调用 `syncAdjustAsOf` 作废旧缓存；窗口内任一页的 `adjust_as_of` 与首页不同（`consistentPages`）时整窗 `resetQueries` 重载 |
| 共用缓存 | 个股页表头（今日开高低收）与图共用同一个日 K 窗口查询，首屏只发一次请求 |
| 分时 / 日 / 周切换 | 分时仍用 `useBarsOf`，按当前周期 `enabled`；K 线 hook 记住最近的日/周周期，切回不重取；新周期数据到达前保留旧图（沿用 T-F22a m17） |
| 通用游标分页 | `lib/cursorPaging.ts`：`useCursorPages`（`limit` 夹在 1–200，非法值回落 50；`flattenPages` 跨页按 id 去重）；`components/CursorPager.tsx`：“已加载 N 条 / 加载更多”，末页“已显示全部 N 条”，下一页失败时保留已加载内容并就地提示、按钮改为“重试”。接入：个股公告页签、管理员用户列表 |
| 表格虚拟化 | `DataGrid` 固定 `rowBuffer=10`（AG Grid 社区版行虚拟化，未引入任何企业包） |
| 批量更新 | `DataGrid` 新增 `batchUpdates`：行集合与顺序不变时只把引用变化的行交给 `applyTransactionAsync({update})`（`asyncTransactionWaitMillis=50` 合批）；行数或顺序变化时先 `flushAsyncTransactions` 再整表 `rowData`。终端自选表启用。判定逻辑在 `components/gridBatch.ts` 的纯函数 `planRowUpdate` |

## 遗留问题

1. 窗口加载只用 `before`+`limit` 向前翻页；契约里的 `from` / `to` 没有用到（没有“跳到某日期”的需求）。
2. mock 只给个股补了历史；指数 K 线 mock 仍是固定长度，指数图会直接显示“已到最早”。
3. 真实浏览器里没有 2,000 行级别的表格可截图（示例数据只有几行），虚拟化由 jsdom 测试覆盖；接入真实数据后建议在性能评审时实测。
4. 契约 v0.2.8（6ef79c4）及之后的 4caedc0（docs(contract)：注册待审核上限 503 REGISTRATION_CLOSED、`/daily-reports` 列表按 date 倒序）未同步；本任务只按 v0.2.7 实现。
