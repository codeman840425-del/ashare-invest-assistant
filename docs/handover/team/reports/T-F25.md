## 做了什么
- 枚举与类型：`security_reconciliation_kind`（vendor_stale_listed / vendor_unknown / quote_missing / quote_conflict / field_mismatch）、`security_reconciliation_source`（mairui_lists / mairui_real_all / cninfo / akshare）；`SecurityReconciliationDiff` 字段与契约一致（id、kind、source、security_code、name、source_name、field、master_value、source_value、licence_owner、first_seen_on、last_seen_on、seen_days、status、resolved_on）。
- 查询：`useAdminSecurityReconciliation(filter)`，§1.2 游标分页（limit 50），`status` / `kind`（逗号分隔多值）/ `source`；不重试。
- 页面 `/admin/securities/reconciliation`（管理员可见，“更多”导航与用户菜单有入口“主数据对账（管理）”）：
  - 筛选：状态（未关闭 / 已关闭 / 全部，默认未关闭）、差异类型（多选）、来源（单选）；与地址栏同步，可直接分享链接。
  - 地址栏里不认识的筛选值：前端忽略、不发给后端（否则会 400），并在页面上提示“已忽略”。
  - 列：最近出现、差异类型（带说明）、证券（主数据无此代码时注明；对方简称）、来源（证书所有人链到数据证书管理页）、差异内容（“字段：主数据 X ／ 对方 Y”）、持续（N 个工作日 / 起始日）、状态（未关闭 / 已关闭 + 关闭日）。
  - 服务端返回不认识的 kind / source / field 原样显示；接口出错显示错误框。
- 采集状态页：`master.<kind>` 告警旁加“查看对账差异”链接（带 `?kind=`）；`master.snapshot_rejected` 没有对应差异类型，不加链接。告警文案仍按 #39 原样显示 `message`，**排序按 #39**（T-F27 已对齐，本项无需再改）。
- 非管理员：路由 404（与其他管理页一致），导航里没有入口（验收 8）。
- MSW 示例：7 条虚构差异（覆盖 5 种类型、4 种来源、一条已关闭），按 `last_seen_on desc, id desc` 排序；status/kind/source 非法值 → 400 VALIDATION_ERROR；非管理员 404。另导出隔离区代码与“本人未关闭 quote_missing”供 T-F26 使用。master.* 告警是否出现仍由 `setMockMasterAlerts()` 显式指定，不从夹具推算（阈值属于后端）。

## 缺失的契约项
1. `source` 是否支持逗号分隔多值：`kind` 写明可多值，`source` 没写。前端按单值发送（单选）。
2. `limit` 的最大值未写（§1.2 通用上限是否适用未说明）；前端固定 50。
3. 是否支持按证券代码 / 关键字筛选（`code` 或 `q`）：未写，前端没有提供。
4. 列表不返回总数（count / total），前端只能“加载更多”，无法显示条数。
5. 两个新枚举没有给中文显示名，前端自拟（`i18n/reconLabels.ts`），需要产品确认措辞；尤其 `quote_conflict` 对普通管理员的含义（与 quote_missing 区别）没有说明。
6. `licence_owner` 对应的用户被删除后是 null 还是保留快照，未写。
7. `seen_days` 的“工作日”是否按交易日历计算未写（前端只显示数字）。
