## 做了什么
### 顶栏证券搜索（`components/SecuritySearch.tsx`）
- 曾用名命中（含曾用名的拼音首字母，`match_kind=former_name`）显示“曾用名：<matched_text>”；排序仍完全按服务端，前端不重排。
- `quote_missing=true` 显示徽标“行情源缺此代码”（悬停说明：行情、K 线可能取不到，档案等公开主数据不受影响）；`false` 与 `null` 都不显示。
- 枚举值不认识时原样显示（type / risk_flag / listing_status / match_kind）。
- #41：
  - 输入防抖 250 ms（保持）；
  - 搜索查询 `staleTime: 0`、关闭窗口聚焦重拉；不写 localStorage / sessionStorage（有用例检查）；
  - 429 不自动重试；按 `details.retry_after_s` 暂停发请求，**冷却期间换词也不发**，到点自动重查当前输入；下拉提示“搜索过于频繁，请 N 秒后再试”。
- 错误提示（下拉内）：400“搜索词不符合要求：<message>”；403 等走通用 `errorText`；414 带信封时按 #34 显示 `message`，响应不是 JSON 时兜底“请求地址过长，请缩短搜索词”；401 仍由全局跳登录。
- q 归一化（NFKC、去空白）后超过 20 个字符：前端直接提示“搜索词最多 20 个字符”，不发请求（契约：超长 → 400）。
### MSW 示例
- 虚构夹具“示例银行”（600000.SH）的曾用名“示例发展”（首字母 SLFZ）：搜 `SLFZ` / `slfz` / `示例发展` 都得到 `former_name`、`matched_text=示例发展`；搜当前简称时 `name_exact` 优先；档案 `former_names` 同步。
- `quote_missing` 按当前用户本人证书：证书 active → 有本人未关闭的 quote_missing 差异为 true（示例：demo_user 的 830001.BJ），否则 false；未设置或不可用 → null；ETF、指数恒为 null。
- 隔离区（未关闭的 vendor_unknown，示例 609999.SH）搜不到，`/securities/609999.SH` → 404。
- `include_delisted` 只收 true / false，否则 400（`fields[0].field=include_delisted`）。
- 429 / 414 只在用例里用 `server.use` 模拟，mock 本身不限流。

## 缺失的契约项
1. `quote_missing` 的“证书不可用”具体指哪些 `data_licence_status`：`quota_exceeded`、`ip_limited`、`pending_verification`、`paused_by_admin` 算不算不可用未写。前端只显示字段，不受影响；mock 只把 `active` 当作可用。
2. `quote_missing=null`（未比对）在搜索结果里要不要提示：契约没给显示规则，前端不显示。
3. `quote_missing=true` 的面向用户文案没有给出，前端自拟“行情源缺此代码”，需要产品确认。
4. 前端对 `/securities/*` 的内存缓存：#41 只写“不缓存（不写本地存储）”。前端理解为不持久化、不把响应当新鲜缓存复用（`staleTime: 0`）；TanStack Query 的内存缓存（gcTime 默认 5 分钟，仅当前页面会话）是否也要禁用未写，未改。档案、K 线等其他 `/securities/*` 查询的 staleTime 本次没有动，请架构师确认是否也要归 0。
5. 429 同时有 `details.retry_after_s` 与 `Retry-After` 头：前端只读 `details.retry_after_s`（客户端拿不到头部）；两者不一致时以谁为准未写。缺 `retry_after_s` 时前端不暂停。
6. 414 的 `message` 文案未在契约里给出（只说信封与 413 同形），前端原样显示。
7. 搜索结果是否显示 `master_as_of`（主数据日期）未写，本次未显示。
