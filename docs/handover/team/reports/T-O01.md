### 安装中遇到的问题与处理
1. **apt 访问 deb.debian.org 被代理拦截**：apt 的 http 请求从透明代理（Pingora）得到 HTTP 500，换成 https 后 SSL EOF。同一地址用 curl 访问返回 200。处理方式：
   - 用 curl 下载 trixie 的 `InRelease` 和 `Packages.xz`，并用 debian-archive-keyring 验签。
   - 再按 `apt-get --print-uris` 下载缺少的依赖 deb，搭一个临时的本地 `file:` 源完成安装。
   - **临时源（`/etc/apt/sources.list.d/zz-tmp-localmirror.sources`、`/tmp/debmirror`）已删除。** Docker 官方源（download.docker.com）本身直连正常。
   - 遗留：Debian 官方源的 apt 仍不可用，以后 `apt-get install` 系统包会遇到同样的问题（见 §9）。
2. **docker0 已存在（<host>/16）**：这是镜像里以前装过的 Docker 留下的。当时是 linkdown 状态，没有成员接口，iptables-legacy 里还有 DOCKER 链，FORWARD 策略为 DROP。处理方式：
   - 把 `iptables`/`ip6tables` 的 alternatives 切到 `iptables-legacy`，让 dockerd 和遗留规则用同一套表。切换前的规则快照在 `/tmp/iptables-legacy-before-dockerd.txt`。
   - dockerd 直接接管了原有的 docker0，地址没变（<host>/16）。它和主机网段 <host>/24 不冲突，所以**没有删掉或改动 docker0，也没有设置 bip**。
   - compose 项目网络由 Docker 自动分配，验收时正常。
