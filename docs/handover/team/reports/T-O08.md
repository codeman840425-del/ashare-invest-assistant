## 5. 备份与恢复

```bash
deploy/scripts/db-backup.sh [--db aia] [--out-dir DIR]        # pg_dump -Fc → <db>-<UTC>.dump + .meta.json（600 权限）
deploy/scripts/db-restore.sh <dump> --db NEW_DB [--drop-existing] [--jobs 1]
deploy/scripts/db-restore-drill.sh                             # 演练（可设 AIA_DRILL_SECURITIES / AIA_DRILL_DAYS / AIA_DRILL_KEEP）
```

**恢复检查**
- 校验 sha256。
- PG 大版本必须一致，TimescaleDB 版本必须完全一致。

**恢复流程**
1. CREATE DATABASE。
2. `CREATE EXTENSION timescaledb VERSION <同版本>`。
3. `timescaledb_pre_restore()`。
4. pg_restore。
5. `timescaledb_post_restore()`。
6. ANALYZE。

**保护措施**
- 拒绝覆盖容器主库（POSTGRES_DB）。验收时实测会拒绝。
- 目标库已存在时，必须加 `--drop-existing`。验收时实测会拒绝。
- 已知问题：`pg_restore -j 4` 会因 TimescaleDB 目录表的循环外键而失败（演练第 1 次实测：dimension_slice FK）。因此默认改成串行。

## 7. dockerd 自启与免 sudo

**环境限制**
- PID 1 是 tini 加 pod-daemon，没有 systemd、cron、rc.local，也不处理 XDG autostart。
- 因此**不存在真正的开机钩子**。

**最小方案**
1. **socket ACL**：`start-dockerd.sh` 每次启动后，以及发现 dockerd 已在运行时，执行 `setfacl -m u:box:rw /var/run/docker.sock`。
   - 生效用户可用 `AIA_DOCKER_ACL_USERS` 配置。
   - 没有用 chmod 666。
2. **登录钩子**：`/etc/profile.d/zz-aia-dockerd.sh`，由 `deploy/host/dockerd-autostart/install.sh` 安装，**已安装**。
   - 登录 shell 时调用 `deploy/scripts/ensure-dockerd.sh`，正常情况下 0.02 s 返回。
   - dockerd 挂了或 ACL 丢了时，在后台、加锁调用 start-dockerd.sh。
3. **自愈**：`compose.sh` 和 `up.sh` 发现 docker 不可用时，会自己调用 start-dockerd.sh。

**验证**
- 杀掉 dockerd 后执行 `bash -lc true`，12 s 内 dockerd 恢复，ACL `user:box:rw-` 也恢复。
- 在组为 `box orbitd`、不含 docker 的普通 shell 里（没用 newgrp 或 sg），直接 `docker ps` 成功。
- 验收中的 `up.sh`、`docker exec` 全程都没用 sudo。

**回滚**

```bash
sudo /workspace/ashare-invest-assistant/deploy/host/dockerd-autostart/uninstall.sh --remove-acl   # 删除钩子和 ACL
sudo setfacl -x u:box /var/run/docker.sock                                                       # 仅删除 ACL
```

整个过程没有重启机器。

## 8. apt 代理修复

**根因**
- apt 默认会查 SRV 记录 `_http._tcp.deb.debian.org`，得到 `debian.map.fastlydns.net`。
- 本机透明代理把外部域名统一解析为 fake-IP <host>，无法按这个主机名路由。
- 结果是 http 返回 500、https 握手 EOF。

**修复**
- 新增独立文件 `/etc/apt/apt.conf.d/99aia-proxy`，内容为 `Acquire::EnableSrvRecords "false";`。
- 源文件和安装、卸载脚本放在 `deploy/host/apt/`。
- 已有的 3 个 sources 没有改动。

**验证**
- `sudo apt-get update` rc=0，全部 Hit。
- `sudo apt-get install --download-only -y hello` 成功（53 kB），下载后已删除该 deb。
- 对照测试：用 `-o Acquire::EnableSrvRecords=true` 时，仍复现 500 错误。

已清理之前的临时文件 `/tmp/aptsp`、`/tmp/https-test.sources`。

**回滚**：`deploy/host/apt/uninstall.sh`。

## 12. 遗留问题

1. 没有真正的开机钩子：机器重启后，要等第一次登录 shell，或第一次 compose.sh/up.sh 调用，dockerd 才会被拉起。如果平台以后提供开机钩子，应改挂到那里。
2. dockerd 每次重启后 socket 会重建。ACL 只有经过 start-dockerd.sh 或 ensure-dockerd.sh 启动才会补上；如果有人手工 `dockerd &` 启动，就需要再跑一次 `ensure-dockerd.sh --wait`。
3. 压缩比是用随机样例数据实测的（5.3–5.7×）。真实行情上线后，建议用 `chunk_compression_stats` 复核，再更新容量表。
4. 当前 box 磁盘为 128 GB，不够全市场 3 年加本地备份；只做 Tier-1 是够的。
5. 并行 pg_restore 不可用，需要串行。大库恢复时间要按演练规模线性估算，并在实库上复测。
6. WAL 归档和 PITR 没有启用（archive_mode off）。启用前需要确定归档存储位置。
7. 备份目前没有定时任务（本机没有 cron）。需要由调度方（routines 或 Celery beat）定期调用 db-backup.sh，并把备份复制到异地。
