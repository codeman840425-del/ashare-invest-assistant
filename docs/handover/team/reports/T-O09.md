### 改了什么（6908fc5，16 个文件）
- `deploy/scripts/seal-keygen.sh`（新）：openssl X25519 → 单行 JSON `{"<key_version>": "<base64 DER>"}`（私钥 PKCS#8，公钥 SPKI）。已有文件不覆盖，用 `ln` 原子安装；密钥不经过 shell 变量、命令行参数或日志；结束时打印备份提醒。支持 `--version N --dir DIR`（轮换用）。
- `deploy/scripts/compose.sh`：解析 `AIA_SECRETS_DIR`（`.env` > 派生 `~/.config/aia/secrets/<卷前缀>`；shell 值不生效；必须是绝对路径且在仓库外）。新增 `--get NAME`。
- `deploy/scripts/up.sh`：密钥缺失时，全新部署（无 `<前缀>_pgdata` 卷）自动生成；已有数据卷则停止并提示从备份恢复。
- compose：顶层 `secrets:`（file 型）、api/ingest 的 `secrets:`，以及 `DATA_LICENCE_SEAL_KEY_VERSION`（默认 1）。`.env.example` 新增 `AIA_SECRETS_DIR=`、`DATA_LICENCE_SEAL_KEY_VERSION=1`（不含私钥变量）。
- CI job `secret-boundary`：`scripts/ci/check_secret_boundary.py`，自测在 `scripts/ci/tests/test_secret_boundary.py`。检查以下几项：
  - deploy/compose、.env.example、deploy/scripts、.github 里没有全站证书变量；
  - 不用 env_file；
  - 私钥 secret、`*_PRIVATE_KEY(S)` 变量和私钥挂载只允许出现在 ingest；
  - secret 必须是 file 型；
  - api 和 ingest 有各自需要的 secret；
  - .env.example 不含私钥。
- 手册：`deploy/runbooks/data-licence-seal-keys.md`，内容包括位置与权限、备份（与数据库备份分开）、轮换与重新封装步骤、冷备切换时带上私钥、开发机恢复生产备份时证书解不开（预期行为）。
