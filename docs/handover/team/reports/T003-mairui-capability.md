- 刷新延迟：文档写券商源“实时”、网络源“交易时间段每 1 分钟”。今天非交易日，返回的是上一交易日（10-30）收盘快照，**盘中延迟无法测，需交易日补测**（方法：盘中连续取 real/time，比较 `t` 与本地北京时间，并对比 ssjy/all 的统一时间戳推进间隔）。

- 无任何限流相关响应头（只有 Date/Content-Type/Server: openresty）。

## 2. 分时与 K 线（部分实测）

| 接口 | 地址模板 | 实测结果 |
|---|---|---|
| 最新 K 线 | `.../hsstock/latest/{code.市场}/{d|w|m|y|5|15|30|60}/{n|f|b|fr|br}/{licence}?lt=1..5` | d/n lt=5 → 200，5 条；**lt=10 → HTTP 422** `invalid lt (must be integer 1-5)`；5 分钟 lt=5 → 200，最新到 2026-10-30 14:40~15:00 |
| 历史 K 线 | `.../hsstock/history/{code.市场}/{级别}/{复权}/{licence}?st=YYYYMMDD&et=YYYYMMDD&lt=` | 日线 n/f/b/fr/br 2025-06-01~10 全部 200 有数据；600519 日线不带区间 → **6106 条，2001-08-27 起**（上市日）；周线 f 200；5 分钟 2020-01-02~03 → **空数组 `[]`**；5 分钟 2026-10-30 → 200 有数据（约一天 48 根）；**5 分钟传 f → HTTP 503 `redis history unavailable (cold fallback disabled): redis history miss`** |
| 1 分钟（Pro） | `.../hsstock/pro/latest/{code.市场}/1/n/{licence}?lt=`、`.../hsstock/pro/history/{code.市场}/1/n/{licence}?st&et&lt` | **未验证**（被 IP 超限中断）。文档：Redis 集群盘中增量，lt≤5 |

| 字段 | — | 日线：t, o, h, l, c, v, a(成交额), pc(前收), sf(停牌标记) |

- 复权口径（文档+实测）：日线及以上 n 不复权 / f 前复权 / b 后复权 / fr 等比前复权 / br 等比后复权，实测五种均返回；分钟级只支持 n（传 f 实测返回 503 数据错误）。
- 回溯长度：日线覆盖上市以来（实测）；5 分钟不到 2020-01（实测空），确切起点**未验证**；1 分钟文档未写深度，需补测。
- 更新时效（文档）：5 分钟线盘中每 5 分钟更新，日线 15:30 开始、约 17:1x 完成。
- **数据疑点（需交易日复核）**：`latest/000001.SZ/d/n?lt=5` 返回的 2026-10-26、27、28 三根日线为 `sf=1, v=0, a=0, o=h=l=c=11.66` 的平价占位行，但同一股票 10-30 实时快照显示正常成交（11.64，成交额 21.5 亿），平安银行这几天并无停牌公告的依据——疑似日线数据缺失被填为“停牌”。若属实，技术指标与回测会被污染，需交易日与 history 接口交叉核对。

## 11. IP 超限根因
- 开发 box 访问外网经透明代理（DNS 返回 <host> 这类假 IP），对不同目的地会走不同出口：访问 ipify/icanhazip 稳定为同一 IP，但访问 checkip.amazonaws.com 连续 6 次得到 **6 个不同公网 IP**。即**出口 IP 随 TCP 连接变化**。
- 探针每启动一个新进程就新建连接：12:07:41（p01）→ 12:08:09（p02 第一次）→ 12:08:35（p02 重跑）三个进程在 60 秒窗口内用了 ≥3 个出口 IP，第 3 个即被 103 拒绝。时间线与“每连接一个 IP”的假设完全吻合。
- 另外，p02 第一次运行中分钟线 f 的 503 被探针保守当作限流停下，我按规则等待后才重跑；脚本已修正为只把明确的数据缺失类 503 排除在熔断之外。
- 由于无法排除其他人同时使用同一证书，**再测前请确认证书没有在别处（本地 IDE、其他服务器、同事）使用**。

## 12. 2 个 IP 限制对服务端架构的影响
1. **单出口行情网关（必须）**：所有麦蕊请求只能由一个“行情网关”服务发出，固定公网出口 IP（云 NAT 网关 EIP 或固定出口代理）。网关集中拉取、写缓存，再向内部服务/客户端扇出。证书只存在网关的密钥管理里。
2. **禁止客户端/多实例直连**：浏览器、App、各业务服务、定时任务、开发者本机都不得直连麦蕊（否则任意 2 个额外 IP 就会把生产网关挤出 60 秒）。开发调试也走网关（或另购一张开发证书）。CI 中禁止带证书的测试。
3. **长连接复用**：即使出口固定，也应在网关内用单个 keep-alive 会话串行（或小并发）请求；本次 box 的教训说明“每次新连接换 IP”的网络环境会直接触发 103。部署前验证出口：连续多次从网关访问外部 IP 回显服务确认 IP 不变。
4. **多副本与故障切换**：网关可多副本，但**同一时刻只有一个主副本持有“拉数据”角色**（基于 Redis/etcd 锁或 K8s Lease 做 leader election），其余副本只读缓存对外服务。所有副本放在同一 NAT 出口之后；切换到另一个可用区/出口 IP 时，新旧 IP 合计不超过 2 个，且旧主必须先停止调用（fencing），切换后 60 秒内不得再出现第三个 IP。滚动发布同理：新 Pod 与旧 Pod 共享同一出口，或先停旧再起新。
5. **缓存与扇出**：
   - 全市场快照每 60 s 拉 1 次写入 Redis（按代码 Hash，带源时间戳 `t`），用户自选的热门子集用多股接口 5–15 s 补刷；对内通过 WebSocket/SSE 推送变化，客户端不轮询麦蕊。
   - 日频数据（日线、财务、因子、资金流日数据、龙虎榜、股池、公告）按文档更新时刻（15:40、16:30、20:00、次日 0 点等）由调度器拉一次入库，用户请求只读本地库。
   - 全局令牌桶（远低于 6000/分钟，如 3000/分钟）+ 每接口独立桶（批量 1/分钟、history/full 60/分钟）+ 因子计次权重；遇 429/103、频率类 503 熔断退避 ≥60 s 并告警；业务错误按响应体（HTTP 200 + error）识别。
   - 单点风险：网关或出口故障时整个产品行情中断，需降级为“显示最后一次缓存 + 时间戳”。
