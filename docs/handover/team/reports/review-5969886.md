## 问题
- **m1** `mocks/handlers.ts:159-162`：其他账户的示例同时带 `cash` 缺口和 `data_status:'fresh'`（注释写的是“没有估算行，不为 partial”），与 R6 ④“其他缺口按 1.1 节取最差状态”不符。#31 ② 已明确：除 `exposure.sector` 外，任一缺口（含 `cash`）都使 `data_status=partial`。应改为 `partial`。
- **m2** `i18n/horizonCaps.ts:38-46`：`horizonDataMissing` 没有排除有 gate 封顶的周期；`noSuitableForLackOfData` 直接看是否存在任一 `data_missing` 封顶，所以一个被硬门槛排除的周期也能让整体显示“数据不足”。现有用例只测了只有 gate 封顶的情况。按 #31 ③ 应改为：该周期有 `data_missing` 封顶，**且没有** `gate` 封顶，才显示“数据不足”；整体显示“数据不足”的条件是 `suitable=[]` 且至少一个周期满足前一条。需补 1 条用例：同一周期同时有 gate 和 data_missing 封顶时，不显示“数据不足”。
- **m3** `mocks/ingestAlerts.ts`：
  - 14 天内到期的告警，key 用了 `licence.<status>`（第 49–50 行，注释自述“待定”），应改为 `licence.expiring`；
  - 文案应改用 #31 的固定表；
  - freshness 和告警文案中的数据集名称，改用 #31 ③ 的中文名。现在 freshness 表格直接显示 key，也应改为中文名。
- **nit1** `AdminIngestPage.tsx:49`：列表的 React key 用的是 `a.key`。#31 规定每个 key 最多一条，所以现在不会出问题；作为防御，可以改成 `` `${a.key}-${i}` ``。
- **nit2** `SuggestionDetailPage.tsx`：头部的 `suitable` 取自候选信号卡上的 `horizon_assessment`（生成时的快照），“数据不足”却取自实时的 `/horizon-assessments`。两者的分类器版本可能不同。建议加一行注释说明，或者统一改用其中一个来源。
