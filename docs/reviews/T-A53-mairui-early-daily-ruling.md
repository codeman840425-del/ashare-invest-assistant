## 0. 输入与边界

- 名单链：`/hslt/list`、`/bj/list/all`、`/kc/list/all` 三个独立 HTTP，字段只含代码/简称/市场，用于 T-A22 的名称与风险标记补全，不能提供日 K。
- T-B90 把 `DAILY_HTTP_LIMIT=1` 作为闭锁；现由本裁定改为 3，但**仅限名单链**，不得借名给行情或探针扩额。
- T-B05/T-B86 探针总授权 128 次及其分类额度不变；本裁定不挪用、不重置、不新建替代台账。
- 提前展示不等于放开实时链路：T-B05 盘中实测、T-B06/T-B22 完整行情链未完成前，只开日级收盘数据。

## R1｜最小行情视图范围冻结（目标 11-10～11-11）

### 1. 数据与证券范围

- 每证书、每交易日只要求本人**持仓 ∪ 自选**中的沪深 `type=stock` 证券，以及后端既有配置的指数清单；北交所、ETF、CDR、可转债不在本最小集，缺数据照既有 null/gap，不为此补调用。
- 只接 `adj_type=none` 的日级数据；只保证本次盘后采集覆盖的交易日，**不做历史回补**。前复权、周 K、1 分钟、盘中快照、实时推送、全市场宽度、涨跌停池、板块/资金流、因子与策略重算均排除。
- 存储复用 plan 既有 `market.daily_bars` 投影及 `source_licence_id` 隔离规则，不新造一套行情公共模型；读取只命中本人证书数据，禁止跨证书回退或共享。

### 2. 最小字段集（不新增响应键）

| 落点 | 字段与映射 |
|---|---|
| 日 K 基座 | `security_code, trade_date, open, high, low, close, pre_close, volume, amount, fetched_at`；`pre_close` 取上游 `pc`，不得用前复权价替代 |
| `GET /securities/{code}/bars` | 仅 `freq=d&adjust=none` 属于本切片；`Bar` 复用既有 OHLC/`pre_close`/`volume`/`amount`，`t=trade_date`、`avg_price=null`、`is_final=true`（仅收盘后成功入库行） |
| `GET /quotes`、`TerminalRow.quote`（`/terminal`、`/today.focus`） | `price=close`；`change_pct=(close/pre_close−1)×100`；`volume`、`amount` 原值按既有单位换算；`t=trade_date 15:00:00+08:00`（日 K 收盘时点，不冒充实時 tick） |
| `GET /market/overview` | 仅配置指数的 `price/change_pct/amount/t` 按上映射；`trade_date` 为行情所属交易日 |

- `pre_close` 缺失/非正、close/volume/amount 缺失或单位未通过校验时：**不生成 quote**，保留 bars 中可核实的字段并列 gap；不得填 0、用成本价或旧快照拼凑。指数可空字段按既有契约置 null。
- `/market/overview` 的 `breadth`、`regime`、`regime_position_range`、`turnover_total` 本切片一律 `null` + 对应 `no_source` gap；不得用本人小样本聚合冒充全市场，也不得默认 `regime=range`。
- 终端/今日页其余账户、建议、风控聚合保持原契约；本切片不承诺 `pnl_day`、市场宽度或策略结论因真实日 K 自动就绪。

### 3. 读取与状态

- 四个端点结构均不变，只读已入库数据。最小切片**不开放按需回补**：缓存缺失返回既有空集/`pending`/`unavailable` + gap，不在 GET 中新增上游请求；`/bars` 原有的自动回补行为在本切片保持关闭。
- `data_status`：要求的最新已覆盖交易日数据齐全为 `fresh`；只有更早数据为 `stale`；部分证券/指数缺失为 `partial`；已授权批次在途但尚无可读行为 `pending`；从未取得为 `unavailable`。`data_as_of` 取本响应实际使用行情时点中的最早值，全空为 null。
- 前端用既有 `trade_date`/`t`/`is_final` 展示“日级收盘”，不得标“实时”；真实数据不得再打“示例数据”，缺失也不得换成 mock。

## R2｜错峰串行规则与配置归属

1. **时间**：仅交易日且日历 `is_open=true`；北京时间 18:00 后才可发起产品名单批次。非交易日、日历未知、18:00 前均 0 次；当日截止 23:59:59，不跨日补打。
2. **次数与顺序**：名单每交易日一个逻辑批次 = 固定顺序 `hslt_list → bj_list_all → kc_list_all`，每端点最多 1 次，共 **3 HTTP**；上一请求结束后至下一请求开始至少 60 秒。失败、超时、STOP 均消耗已预留次数，无上游重试、不换路径。
3. **探针避让**：T-B05/T-B86 任一批次在运行、持有外呼锁或存在结果不确定的在途请求时，产品不得发起；反方向同样。重叠时探针优先，产品等下一本地 tick；截止仍未获得锁则 expired，不把等待变成额外 HTTP。
4. **互斥**：产品名单、产品日 K、T-B05、T-B86 全部使用同一 `ingest:single-egress` 互斥与逐请求检查，不能仅靠“18:00 通常没探针”的时间假设。日 K 也只在 18:00 后的产品串行窗口运行。
5. **配置归属**：目标键归入 `config/ingest.yaml` 的 `licences.product_daily`（名单窗口、3 次、60 秒、同一互斥/停机键），调度仍用既有 beat/worker/outbox，不新建第二套调度器。为避免 `extra="forbid"` 导致旧后端启动失败，本单只在 plan 登记 schema 与默认值；实际 YAML 和 pydantic 校验由后端实现同一提交补齐，架构师不单独先写运行配置。

建议目标键（实现时不得改语义）：

```yaml
licences:
  product_daily:
    not_before: "18:00"          # 北京时间；仅已覆盖的交易日
    deadline: "23:59:59"
    list_datasets: [hslt_list, bj_list_all, kc_list_all]
    list_max_http_per_day: 3
    min_interval_s: 60            # 上一请求结束到下一请求开始
    upstream_retry: 0
    exclusive_lock: "ingest:single-egress"
```

## R3｜共用停机门禁与通知

1. **同一门禁**：产品与探针在每次请求前、60 秒等待后、下一请求前都检查同一证书停机状态；公共 `STOP` 为全局停机。任何一侧发现 `STOP`、上游业务码 103 或 HTTP 429（含 HTTP 200 包裹错误、纯文本 103），立即停止后续请求。
2. **影响范围**：`STOP` 停全部证书；103/429 停该证书的产品与全部探针调用，并锁存当前批次。请求已发出则在该侧原台账计 1 次，不能因结果不确定重放。
3. **锁存与恢复**：保留既有 `data_licence_status=ip_limited`、`paused_until`（120 秒；1 小时第 3 次为 1 小时）供展示；但本错峰共存期另有持久 `halted` 闩锁，**到点不自动恢复外呼**。只有 Chief/授权运维确认另一侧已停、距最后请求 ≥60 秒且出口唯一后，才能按当次指令清除产品和探针两侧闩锁；被中断的探针批次不续跑，产品当日失败批次不重试。
4. **通知**：复用既有 `data_licence` 站内通知 + 管理端 IP 超限告警，按证书和状态跃迁只发一次，不能产品与探针各刷一条；内部 detail 可含 `trigger_source=product_daily|probe_tb05|probe_tb86`、`upstream_code=103|429|STOP`、`paused_until`、停止范围，不含证书、完整 URL、原始 body 或账户信息。全局 STOP 只通知管理员；本切片不新增邮件或其他外发通道。
5. 其他 101/102/503 仍按 plan §2.1B 既有规则；探针自身更严格的失败即停规则不放宽。

### R3A｜单证书闩锁作用域与关联清理（T-A54 补充，北京 2026-11-09）

1. **按证书隔离**：103/429 的执行闩锁必须以稳定 `licence_id`（冷却 tombstone 可另存既有证书 HMAC 指纹）为作用域；门禁求值是「当前请求证书是否有有效闩锁」，**不得**用 `exists(any halted)` 阻断全部证书。只有公共 `STOP` 是全局闩锁。产品与探针共享的是同一证书的闩锁，不是跨证书共享 103/429 状态。
2. **关联清理即执行面失效**：DELETE 证书、账号/证书关联清理或周期 purge 后，遗留闩锁立即标记为 detached/孤儿子记录，不再进入任何有效证书的门禁求值，尤其不得阻断其他证书；没有有效授权与证书关联时，该遗留记录本身也不可能放行原证书调用。公共 STOP 不随任何证书清理而失效。
3. **与契约 §7.1 DELETE 冷却语义对齐**：执行面失效不等于抹掉历史。审计与原批次记录保留；冷却 tombstone 仅在契约既有保留期内保存证书指纹、删除前 `status/ip_limited` 与 `paused_until`，供**同一证书**在冷却期内重新 PUT 时恢复原状态及该证书闩锁。不同证书、新 `licence_id` 或其他用户均不继承。
4. **到期彻底失效**：tombstone 到契约期限后视为不存在并周期清除，不能再用于恢复闩锁；此后同一证书也按新提交验证。清理 orphan/detached 闩锁不等于人工解除一个仍有效证书上的 103/429 闩锁，后者仍须 R3 第 3 点授权双侧解闩。
5. **未知作用域例外**：迁移前遗留且无法证明所属 `licence_id`/指纹的 103/429 闩锁不得自动当成孤儿子记录或全局共享记录；为防误放行，保持全局停机，由授权人员核查后显式归档或绑定，不能靠 TTL 猜测解除。
6. **定点负例**：A 证书闩锁只停 A、B 照常；删除 A 关联后 B 不受阻且 A 无调用；冷却期内重新提交同一 A 恢复 A 闩锁，换证书/逾期不恢复；公共 STOP 仍停 B；未知作用域旧闩锁保持停机，不能自动失效。

## R4｜预算裁定：3 对 1

- `DAILY_HTTP_LIMIT` 的契约值改为 **3**；T-A22 的“每个交易日 18:00 取 1 次”明确为“**1 个逻辑批次、3 个独立 HTTP**”。完整名单没有单接口替代依据，不能把调度批次伪装成 1 HTTP。
- 名单台账（建议 `mairui-daily/v1`）按交易日独立计数：成功完整批次 3；非交易日 0；失败/STOP 为实际已预留的 0–3；第 4 次必须在建连前拒绝。
- **3 次只覆盖名单，不是日 K 配额。** 最小日 K 走既有盘后 P1 队列与证书令牌桶，按实际请求另记产品日账，执行次数仍须当次授权；不得占 T-B05/T-B86 的 128，也不得把探针原始样本直接当产品数据。
- “另账”不等于另令牌桶、另证书或另并发：所有产品/探针请求仍扣同一证书每分钟预算并受同一单出口互斥。

## 5. 不兼容点与例外

- API 字段、枚举、路由均无新增；仅把最小切片的 `/bars` 自动回补暂时收紧为不投递，读取缺数据更显式 pending/unavailable。
- 103/429 的既有 120 秒/1 小时状态展示不变，但本错峰期恢复外呼改为人工解除持久闩锁，严于原自动恢复。
- T-A22 的每日 1 次更正为 1 批次 3 HTTP，是本次明确预算修订；其他任务次数不受影响。

## 6. 验收口径（实现/测试按此定点）

1. 名单：17:59、非交易日、日历未知均 0；18:00 后三端点顺序执行、间隔 ≥60 秒、第四请求建连前拒绝；失败消耗且无重试。
2. 错峰：探针持锁时产品 0，产品持锁时探针 0；两侧台账各自计数，128 不变；跨日不补打。
3. 停机：分别从产品、T-B05、T-B86 注入 STOP/103/429，另一侧同证书后续调用均为 0；通知不重复、不泄密；未经人工双侧解闩不恢复。
4. 视图：用合成日 K 验证 close/pre_close/volume/amount/15:00 映射；缺 pre_close 不出 quote；无数据不读 mock、不触发 HTTP；breadth/regime/turnover_total 为 null + gap。
5. 隔离：用户 B 不能读到或触发用户 A 证书的数据/调用；普通用户不能清公共 STOP/停机闩锁。
