## Q-01｜G1「每个周期至少一条 exit」的多周期口径

**裁定：声明即适用。** 多周期卡（`horizons` 长度 > 1）的 exit 规则一律视为对声明的全部周期适用；G1-02 的机器判定 = exit 规则集非空且含止损类（F7），不要求按周期各写一条，也不允许按「部分周期适用」勾选通过。

- 卡片 schema 支持按规则标注适用周期（须另走契约裁定新增字段）之前，不引入部分适用语义；研究员文档里的适用性说明只是 narrative，不参与机器判定。
- 某卡确有仅部分周期适用的 exit 时：改单周期卡，或先走契约裁定定字段；不得静默按部分适用通过 G1。
- 理由：plan G1 措辞定稿时只有单周期卡；T-A48 R1 已确立「卡片层多周期适用、实例层单值」两层语义，H-01 的 MA60/ATR 型离场对任意持有周期都成立。按周期拆分 exit 会强制 H-01 出 v3，违反 T-A48 R1「不为此出 v3」。
- 对 T-R24 清单：M-02 第一句确认；第二句（「若某周期不适用，须逐条写理由与替代退出规则」）改为本条口径。

## Q-02｜T-A14 ③「一项都不豁免」与 H-01 G1 豁免的字面冲突

**裁定：表述澄清，不改裁定实质。**「一项都不豁免或放宽」指 G1–G7 七道关卡**一道不能整关跳过、不能放宽判定标准**；关卡内部已登记的角色型豁免照常有效——G1 对纯离场组件（`mount_policy=system_only`、无 buy/add）免 entry（T-A03、T-R15 ②）、G2 的 `insufficient_data` 不算失败（§2.5.0B G2）等——但每个豁免必须能指到登记的裁定条号。

- T-A14 ③ 自身下一行即承认 H-01 豁免，原意即此；冲突源于措辞压缩。plan §2.5.13 T-A14 ③ 已补澄清句（随本裁定提交）。
- 对 T-R24 清单：§0.2「[-] 不适用」两种情形的写法与本裁定一致，无需改。

## Q-03｜新多周期卡（H-01 以外）能否直接晋级

**裁定：确认 M-07 阻塞口径。** plan §2.5.0B 允许多值 `horizons` 是 **L1 卡片字段格式许可**，不是晋级许可；与 T-A48 R6 合流后的口径：新多周期卡在取得架构师裁定（二选一：① 收敛为唯一版本周期（出版本）；② 定义结论绑定语义——每条结论显式绑定 horizon 或显式全周期适用 + 实例单值消费语义）之前，不得提交晋级。

- 无裁定时研究员预检按「未执行/阻塞（M-07）」记，不提交 G7；卡片照常可入 L1 知识库、作说明页引用。
- 若已提交跑 G1：G1 记 fail，detail 写明「多周期卡缺周期裁定」。
- H-01 不受影响（T-A48 R1 已裁定 swing 挂载）；R1 不沿用到其他卡。
