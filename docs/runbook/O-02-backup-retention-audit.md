## 实现与文档

- `deploy/scripts/db-backup.sh` 默认写入 deploy/backups，可由 AIA_BACKUP_DIR/--out-dir 改位置；UTC 秒级时间戳命名，pg_dump custom format，默认压缩级别 6，产物 dump+meta 均 chmod 600。
- 脚本对每次成功备份记录 PG/TimescaleDB 版本、镜像、大小和 SHA256；仅在当次 pg_dump 失败时删除当次 dump、结束时删除临时 stderr。**没有按份数、天数或容量轮转，也没有清理历史 dump 的逻辑。**
- `deploy/runbooks/database.md:189–191` 写「本地保留 2 份」，是容量规划口径，不是当前脚本已执行的策略。deploy/ 脚本未发现相应保留清理命令；未据此推断 Windows 任务计划程序/WSL crontab/外部平台一定无任务（本单未逐一核查）。
- deploy 目录里的 TimescaleDB 行保留策略、容器日志轮转，均不等于 dump 文件保留策略。db-restore-drill 的临时演练清理也不管理正式备份。

## 清理建议（仅建议，当前删除 0 份）

1. 先建立非秘密 manifest：每份 dump/meta 的绝对路径、字节、SHA、PG/TS 版本、备份用途、部署/迁移关联、恢复验证状态与 hold 原因；不能只按 mtime 或扫描一个目录取最新两份。
2. 以手册「普通本地至少最新 2 份」为最低建议，同时对每次未验收迁移/部署的前置备份加独立 hold；新备份即使成功也不能立刻挤掉唯一已验证恢复点。T-O45 0029 前与 T-O79 升级前等历史保护点由编排者逐一确认是否仍需保留，不能本单替其解除。
3. 每次清理前，至少有一份新鲜完整备份在**新校验库**恢复成功，核对版本/用户数/表数与业务验收；失败不清理。dump+meta 同生共存，验证后再成对列候选。密钥备份须按手册与 dump 分开保管，不借盘点读取它。
4. 先 dry-run 生成路径白名单，人工核 hold 和回滚窗口；另单授权后才清理。不要 `find -mtime ... -delete` 或按全盘 *.dump 通配删除；拒绝越目录、软链和解析结果不在登记目录的目标。
5. 建议用软告警而非自动删最后恢复点：正式备份目录达到批准容量预算的 80% 告警、达到 90% 暂停非必要备份并报编排者；数值是待批准建议，不能让容量策略跳过部署前必需备份。备份失败则该部署停止。
6. 正式轮转实施单应分别测试：最新两份保留、hold 不删、无 meta/错 SHA 隔离、恢复失败不清理、越界/软链拒绝、清理失败不影响新备份、并发备份不会删在写文件。只跑定点检查。

备份可能含真实业务数据与加密字段；本单仅记录大小、版本与完整性结果，不上传 dump、不打印内容、不自动归档到公网。也不执行 down -v、卷清理或账户删除。
