## 3. 匹配算法（确定性，按序执行）

参考实现 `T-R62/match_f23_v3.py:match_detail()`，顺序不可调整：

1. **归一化**（§2）。
2. **整条排除**：标题为空 / 命中中介前缀正则 / 含任一 `title_excludes` → `excluded=True`。
3. **政策规则**（先于类目）：
   - `inquiry_transfer_policy`：标题含「询价转让」→ **一律命中**，**优先于整条排除**（澄清、中介文件、撤销/终止/不实施也命中），无否定豁免；
   - `concert_change_policy`：含主体（控股股东/实控人/一致行动人）+「一致行动」+ 事件（到期/解除/终止）+ 变动（权益变动/持股比例变动/股份变动/持股变动）→ 命中；**仍受整条排除约束**。
4. **若 `excluded` 且政策未命中 → 判否**（政策命中仍返回，见上）。
5. **逐类匹配**（子句内）：每类先按子句做「他方主体」排除（`exclude_all_of`，见 §3.1①）——只排除命中且对象为他方的那**个子句**，不跨子句、不吞整类。关键词每次出现，若前文有否定词且其后无重置词，或后文窗口内有后置否定词 → 该次出现被否定；否定词若为渠道型（以「通过」结尾）且同子句另有无否定的渠道词，则不否定（见 §3.1②）。**任一次未被否定即命中**。
6. **`controller_equity` 专用算法**（顺序固定）：
   1. 去掉「非控股股东/非实际控制人」后找主体；无主体 → 不计（标题含「询价转让」另标 `subject_unknown`）。
   2. 有下降词（减持/减少/下降/降至/降低/询价转让/变卖）且未被否定 → 命中，标 `direction_down`。
   3. 有上升词（增持/增加/上升/提高/受让/认购/被动增加）→ 不计，标 `direction_up`。
   4. 只有变动词（权益变动/持股比例变动/股份变动/持股变动）时：含中性排除（被动稀释/一致行动协议/表决权/继承/分割/赠与/划转）→ 不计（`neutral_change`）；否则**保守命中**标 `direction_unknown`（FP-3 即此类，见 §7）。
7. **判定**：任一政策规则或任一类目命中 → 该公告计 1（多类命中仍只计 1，类别并记）。

**边界事实**：v2 相对 v1 在 153 条回归用例里只有 1 处有意行为变化（天力锂能「司法变卖完成过户…」由否变是）；v3 词表相对 v2.1 只有上述 3 处，`check_f23_v3.py` 用**完整结构差异断言**（递归展平逐路径比较，差异路径必须恰好 = 三处 + 版本元数据）锁定。

### 3.1 T-R63/T-R63b/T-R63c 作用域与坐标返修（RV-20 系列；只改匹配器，词表未改）

1. **他方事件「等长屏蔽」（T-R63b P1a + T-R63c P1）**：`exclude_all_of` 组 = [动作词, 风险事件词]（v3 三条均为「参与/认购 + 破产重整/重整投资」）。只有对象短语判定为他方（他方标记 他方/对方/第三方/其他公司/他公司/另一公司/某公司/对外/外部，或公司名）时，才把「动作词→事件词」这段用**等长屏蔽标记**替换（私有区字符，不删字符、不拼接）——关键词匹配与否定窗口都在**原始坐标**上进行，同子句自身风险词（如「债务逾期」）仍可命中，且「已解决」等后置否定不会因抹除缩短间距漂移进窗口。自身称谓（本公司/我公司/公司自身/公司本身/发行人/本公司及关联主体/及其子公司/及其控股子公司）→ 不屏蔽；**对象不明的中间态一律不屏蔽**（保守=宁误报不漏报；veto 场景有 FP 如实报告兜底）。
2. **渠道否定整段标记 + 绑定最近减持事件（T-R63b P2 + T-R63c P2）**：从每个渠道否定短语（不通过/未通过/不会通过）起点向右，把连续「分隔符+渠道词」整段标为否定（嵌套渠道词「集中竞价交易」里的「竞价交易」随整段幂等，回看到子句边界、不按字数）。渠道的肯定/否定**绑定最近的减持事件**（作用域 = 该减持事件动词前的修饰段）：否定短语与本次关键词之间出现其他事件词（如增持）时，该否定属于更早事件、不适用于本次；同修饰段内存在未被否的渠道（如「而通过大宗交易」）时，该次「减持」仍成立。反例「控股股东不通过集中竞价而**通过大宗交易减持**」→ 命中；「控股股东通过大宗交易**增持**而不通过集中竞价减持」→ 不命中（增持的渠道不跨事件）；「不通过集中竞价**增持而减持**」→ 命中（否定只否增持）。

## 4. 计数与 PIT 口径（`f.ann_risk_count_10d`）

对齐 `feature_spec.md` F23 条，任何实现都必须同时满足：

1. **窗口**：含评估日 D 在内共 **10 个交易日** `[D−9, D]`（按交易日历，不是自然日）。
2. **可得时点 `available_from`** = `max(t, first_seen_at)` 各自生效时刻：
   - 交易日且时刻 < 09:30（含盘前）→ 当日 09:30；
   - 恰好 09:30、盘中、午休、11:30/15:00 边界、盘后、非交易日 → **次一交易日 09:30**；
   - `t` 只有日期（V7 实测如此）→ 次一交易日 09:30；
   - `t` 与 `first_seen_at` 都未知 → `None`，该记录使当日值判为 `null`。
3. **可见判定**：`available_from ≤ D 09:30` 且其北京日期落在窗口内；`as_of < D 09:30` → 当日值尚未生效，返回 `null`（不是 0）。
4. **去重**：主键 `nr`；次键 `(security_code, 去版本后缀标题, 可交易日)`；两者任一相同即**传递归并**（并查集），每个实体最多计 1，结果与输入顺序无关。版本后缀正则 `[（(](更正后|修订稿|修订版|更新后|英文版|更正)[）)]$`。
5. **null ≠ 0**：数据源缺失或新鲜度不达标 → `null`，买入方向草案被 `KEY_DATA_MISSING` 阻断；数据新鲜且无命中 → `0`。**不得把缺失写成 0**。
6. **只挡买入/加仓**：N-01 按 `count > 0` 否决买入方向；卖出方向不受影响（T-R22 裁定 ②）。simulating 期间否决率记入 G6 观察项。
